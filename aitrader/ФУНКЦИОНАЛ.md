# abc — технический разбор функционала

Терминал скрининга и полуавтоматической торговли мемкоинами Solana.
Backend: **FastAPI** (`app.py`), фронт: одностраничный `static/index.html` (тема «violet liquid-glass»).
Философия: **детерминированное ядро решает**, LLM только объясняет выживших; **человек в цикле** (по умолчанию ничего не исполняется само).

---

## 1. Архитектура (модули)

| Модуль | Назначение |
|---|---|
| `app.py` | Ядро: пайплайн скрининга, гейты, скоринг, риск, позиции, PnL, API, все эндпоинты |
| `dexadapter.py` | Бесплатные данные без ключей (GeckoTerminal + DexScreener + Solana RPC) + on-chain проверки (top10, fresh-wallets) |

| `kol.py` | Twitter/X KOL-сигнал (per-user Bearer): упоминания CA, рейтинг авторов |
| `xapi.py` | X-провайдер getxapi.com: reuse-детектор хендла + история ренеймов (memory.lol) |
| `rugcheck.py` | Он-чейн риск холдеров (бандлеры/инсайдеры/danger) — белый лейбл |

## 2. Источники данных (адаптеры)

Выбор адаптера (`MarketLayer.adapter_for`):
- **`GMGN_API_KEY` задан → LiveGMGN** (через `gmgn-cli`, канонический источник: smart-money, KOL, бандлеры, dev-hold, холдеры). Ключ перебивает `DATA_SOURCE`.
- **`DATA_SOURCE=dex` → DexAdapter** (бесплатно, без ключей): GeckoTerminal trending + DexScreener (цена/ликвидность/моментум/socials) + Solana RPC (mint/freeze authority). Smart-money поля = нули, `provides_consensus=False`.
- **иначе → Mock** (детерминированный синтетик для демо/тестов).

Кэш трендинга общий на `MarketLayer` (TTL `TRENDING_CACHE_TTL`, дефолт 20с) → все табы/бот/юзеры переиспользуют один запрос; **backoff на 429** (кулдаун `TRENDING_COOLDOWN_S`=60с, отдаёт кэш/пусто, не долбит GMGN).

## 3. Пайплайн скрининга (`screen_once`)

```
trending (top-N) → build features → hard_gates → scoring → cut to llm_max → LLM judge → ACTION-кандидаты (не исполняются)
```

### 3.1 Жёсткие гейты (`hard_gates`) — детерминированные, без синтетик-скора
**Gate 1 (безопасность/фильтры):** honeypot, не сдан mint (можно допечатать), не сдан freeze (можно залочить продажу), min/max ликвидность, объём 1ч, mcap, возраст, снайперы, объём/ликвидность (刷量), символ/адрес в блэклисте, tax (EVM), rug-ratio, bundler%, dev-holding%, top10-концентрация.
**Gate 2 (консенсус):** smart_degen + renowned KOL ≥ порога (пропускается для источников без smart-money, чтобы честные нули не убили весь список).

Причины отказа — на английском (`REJECT safety/filter/consensus/ranking: …`).

### 3.2 Скоринг (`priority_score`, 0–99)
Взвешенная сумма нормализованных субскоров: моментум 5m/1h, перевес покупок (buy_ratio), оборот (turnover), консенсус (сублинейно), безопасность (renounced + рассеянность top10). При падении 1ч — общий множитель ×0.4. **Edge-weighting**: бонус за tracked-кошельки в монете, взвешенный доказанным эджем каждого (`wallets.edge_weight`). + скорость набора холдеров (holder_velocity).

### 3.3 LLM-судья (`LLMJudge`)
Провайдеры (`GMGN_LLM_PROVIDER`): `heuristic` (без сети, дефолт) | `claude` | `deepseek` | `openai_compat`. Судит **только выживших** (llm_max), параллельно. Возвращает verdict (pass/watch) + conviction + crowdedness + thesis. Числа (размер позиции) LLM **не выдаёт** — их считает код.

## 4. Независимая проверка качества токена (не GMGN-агрегаты)

Идея: GMGN-метрики можно накрутить → проверяем он-чейн/сторонними источниками. Всё **opt-in** и **on-demand** (кнопка Verify), сводится в `/api/token/quality` + единый `red_flag`.

| Сигнал | Как | Флаг/ключ |
|---|---|---|
| **Top-10 концентрация** | Solana RPC `getTokenLargestAccounts`+`getTokenSupply`, крупнейший аккаунт (LP-пул) исключён | `ABC_TOP10_RPC=1` |
| **Свежие кошельки** | RPC: топ-холдеры → владельцы → `getSignaturesForAddress`; свежий = <100 tx за жизнь И первая активность <`ABC_FRESH_AGE_H`(48ч) | `ABC_FRESH_WALLETS_RPC=1` |
| **X-reuse** | getxapi: возраст аккаунта + подписчики + сколько РАЗНЫХ CA постил хендл (серийный шиллер) | `GETXAPI_KEY` |
| **Ренеймы хендла** | memory.lol (бесплатно, без ключа): история имён; ≥4 = красный флаг | — |
| **Фермы (кластеры)** | топ-покупатели по объёму → история каждого (gmgn `portfolio activity`) → union-find по общим токенам; ≥3 коша с общей историей = ферма | live GMGN + `/api/token/farm` |
| **Риск холдеров** | RugCheck free API: бандлеры/инсайдеры/danger-риски/rugged (белый лейбл — имя источника в UI не показывается) | — |

`red_flag` = x-reuse red **или** ренеймы red **или** holders-risk red **или** fresh_ratio≥50% **или** top10≥60%.

## 5. Исполнение (non-custodial)

- **Сборка tx на сервере** (`execution.py`, Jupiter v6) → подпись в браузере (**Phantom**, web3.js). Приватный ключ юзера **не покидает браузер**. Эндпоинты `/api/tx/build` → `/api/tx/confirm`.
- **N3-автопилот** (`sessionwallet.py`): session-кошелёк на сервере (solders, chmod 600), риск = его баланс. Реальные сделки **только при `ENABLE_LIVE_TRADING=1`**.
- **LiveGMGN swap** (`gmgn-cli`) — для оператора; опрос ордера до терминального статуса.
- **Условные ордера** (on-chain TP/SL со swap): `GMGN_ENABLE_CONDITION_ORDERS=1`, по умолчанию ВЫКЛ и не валидированы.

### Режимы бота (`bot.py`, per-user)
- **N1** — очередь предложений: бот предлагает, юзер жмёт ✓/✗ (`/api/bot/proposals`).
- **N2** — полуавтомат (дефолт): бот исполняет через `do_buy`/`do_sell`.
- **N3** — автопилот через session-кошелёк.

Переключение на лету (`bot.cfg["mode"]`). Автостарт: `BOT_AUTOSTART`.

## 6. Выходы: TP-лесенка / трейлинг / стоп (`bot.decide_exit`)

Приоритет: **жёсткий стоп** (−35%) > **escape** (severity ≥ порога) > **трейлинг** (откат ≥25% от пика после активации) > **TP-лесенка** (+60%→продать 40%, +150%→30%; одна ступень за тик, `tp_taken` без повторов).

⚠ **Работает только пока крутится бот** (N2/N3). На ручной покупке без бота автостопа нет. Это софт-монитор, не on-chain.

---

## 7. Риск-менеджмент (`RiskManager`)

- **Размер позиции**: фиксированная доля риска / стоп-дистанция, масштаб по conviction LLM и тиру ликвидности (тонкая ликвидность → ×0.5), кап `max_per_trade_sol`.
- **Портфельные лимиты**: макс. одновременных позиций, общий敞口 (exposure cap), дневной лимит убытка.
- **Kill-switch**: после N подряд убытков (дефолт 3) — блок новых входов (`halted`). Счётчик серии сбрасывается на выигрыше.

---

## 8. Escape-мониторинг (`assess_escape`)

Для открытых позиций сравнивает «сейчас vs вход»: новый honeypot (+60), возврат mint-права (+55), рост top10 (+22), **вывод ликвидности** (−40%→sev45 / −65%→sev70, ликвидность реальна из DexScreener), **обвал цены** (−50%→40). Стабильно — показывает живой статус (mint/freeze renounced, top10). Severity ≥ порога → бот выходит.

---

## 9. Позиции и PnL

- Позиции per-user (файлы `outputs/users/<pk>/` или общий `outputs/`), с `entry`-снепшотом (для escape-диффа), `entry_attrib` (кто был в монете), `entry_liq`, `entry_price`, `peak_pnl`, `tp_taken`.
- **PnL-календарь** (`/api/pnl/calendar`): дневной реализованный PnL из SELL-записей журнала, клик по дню → список сделок (символ, CA, время, %, ◎). **Fee-aware**: net = gross − round-trip cost (`ABC_FEE_PCT`/`FEE_ROUNDTRIP_PCT` ≈2.5%: pool fee+priority+slippage, обе ноги).
- UI: календарь слева, трейды дня справа (двухколоночно).

## 10. Самообучение (offline review-loop, `review.py`)

**НЕ deep RL** (мемы нестационарны). Механика:
1. **Атрибуция исходов** («топливо»): при формировании ACTION-кандидата снимок `entry_attrib` (tracked-кошельки/KOL/priority/фичи), едет с позицией, при закрытии → в SELL-запись (`attrib`+`hold_min`). Каждая реализованная сделка размечена.
2. **`wallet_edge`**: реализованный эдж каждого кошелька из закрытых сделок. **`edge_weight` нейтрален (1.0)**, пока сделок < `MIN_TRADES=5` на кошелёк (не учимся на шуме).
3. **`kol_review`** — надёжность KOL (winrate/медианный пик). **`social_edge`** — X-хайп на входе vs исход.
4. **`propose`** — конкретные правки конфига (min_priority/max_age_min/buy_ratio_reject/min_smart_money_confluence), применяются **только вручную** (`/api/review/apply`, human-in-the-loop, white-list кнобов).

**Тумблер** (вкладка Review, owner-gated): `ABC_SELF_LEARN` / персист `self_learn.json`. При OFF — `edge_weight`=1.0 (нейтрально, старое поведение). **По умолчанию ВЫКЛ.**
**Ночной цикл**: `ABC_NIGHTLY_REVIEW=1`, час `ABC_REVIEW_HOUR` (UTC) — пишет веса/отчёт, ничего не применяет сам.

⚠ Веса появляются, только когда `attrib.tracked` заполняется (нужен live GMGN + `GMGN_WALLET_HOLDERS=1`) и накопится ≥5 сделок/кошелёк.

## 11. Снапшоты (`db.py`, SQLite)

`ABC_SNAPSHOT_DB=1` → каждый скрин-проход пишет ряд на каждое решение (адрес, символ, action, гейт, priority, top10/bundler/dev, smart-money, holders, атрибуция, fresh_wallets) в `outputs/abc.db` (или `ABC_DB_PATH`). Реляционная база под анализ эджа/паттернов/кластеризацию ферм. `GET /api/snapshots`. Прюн по возрасту.

---

## 12. Мультиюзерность и аутентификация

- Заголовок **`X-Wallet`** разделяет `UserSession` (mode/filters/positions/risk/bot/strategy/twitter per pubkey). Общий `MarketLayer` на ключе оператора.
- **Sign-in-with-wallet** (ed25519 challenge→Phantom signMessage→verify, pynacl+base58, токен `X-Auth`). Токен per-pubkey в localStorage, авторетрай на 401.
- **Owner-gating** (`_block_if_not_owner`): house-level тюнинг (review/config) — только `ABC_ADMIN=1` **или** дефолтная сессия (без кошелька).
- **`PUBLIC_DEMO`**: публичная read-only витрина (фоновый broadcast кэша, гости не триггерят cli).

---

## 13. Стабильность / производительность

- Кэш трендинга 20с + backoff на 429 (защита от бана GMGN).
- Кэш holders по токену (90с); holders-пересечение с 293 кошельками — **только для финалистов** (llm_max), параллельно (иначе `/api/run` таймаутит).
- `gmgn-cli` таймаут `GMGN_CLI_TIMEOUT` (12с, fail-fast).
- Rate-limit `/api/run` per-user (`RUN_MIN_INTERVAL_S`).
- Фронт: keyed-рендер строк (переиспользование `<tr>`), грейс-мёрдж (токен не пропадает при моргании из трендинга), транзиентные 429/502/503 пропускают цикл (не паузят опрос).

## 16. Режимы SHADOW / LIVE

- **SHADOW** (дефолт) — бумага: полный движок на реальных данных, ордера не уходят on-chain, PnL считается. Накапливает топливо для review-loop.
- **LIVE** — реальные сделки (нужен `ENABLE_LIVE_TRADING=1` + подписывающий ключ/Phantom). Per-user переключение.
