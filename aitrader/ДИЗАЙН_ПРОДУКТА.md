# 🏗️ ABC — Дизайн продукта (v2: для внешних трейдеров)

> Этот документ фиксирует архитектурные решения, принятые вместе. Код по нему — отдельным этапом.
> Статус: **дизайн утверждён, реализация не начата.**

---

## 1. Что за продукт и для кого

**ABC** — платформа скрининга и торговли соланскими мемкоинами с дисциплинированным конвейером
(антискам → ранжирование → LLM → кандидаты → бот) и пошаговой воронкой риск-контроля.

**Пользователь = внешний трейдер** (не только владелец). Значит:
- ключи доступа к данным — на сервере, юзер их не видит;
- деньгами юзер распоряжается сам (non-custodial);
- у каждого юзера свои настройки, стратегия и портфель.

---

## 2. Модель кошельков: NON-CUSTODIAL ✅ (утверждено)

Юзер подключает **свой** кошелёк (Phantom / Solflare). Подпись сделок — **в его браузере**.
Сервер приватный ключ **никогда не видит и не хранит**.

**Почему так:** нет ответственности за чужие деньги, нет регуляторных кошмаров, максимум безопасности.

**Поток сделки (вместо серверного исполнения):**
```
юзер жмёт «купить»
  → СЕРВЕР строит транзакцию (Jupiter Ultra / Beam), НЕ подписывает
  → отдаёт неподписанную tx в браузер
  → кошелёк юзера (Phantom) показывает «подтвердить»
  → юзер подписывает → tx уходит в сеть
```
Сервер = «конструктор сделок». Подпись = на стороне юзера.

## 4. Режимы исполнения бота (N1 + N2 — утверждено)

Бот всегда ищет сигналы по стратегии. Отличается только **что он делает с найденным** — юзер переключает:

| Режим | Что делает | Подпись | Когда |
|---|---|---|---|
| **SHADOW** (бумага) 🟢 по умолчанию | считает виртуальный PnL, копит статистику | не нужна | обучение, проверка стратегии |
| **MANUAL (N1)** | бот находит → показывает юзеру → юзер жмёт «купить» по одному | юзер подписывает каждую (1 клик) | осторожная реальная торговля |
| **SEMI-AUTO (N2)** | бот сам шлёт сделки | Phantom просит подтверждение на каждую | активная торговля, юзер у экрана |
| **AUTO (N3)** 🔴 будущее | полный автопилот без подтверждений | session-key / делегирование | отдельный поздний этап |

**Важный честный факт:** при non-custodial бот **не может торговать, пока юзер «спит»** — каждая
реальная сделка требует живой подписи. Полный автопилот (N3) возможен только через session-keys
(делегирование ограниченных прав) — это отдельный большой этап, не сейчас.

## 5. Что меняется в архитектуре (single-user → multi-tenant)

Сейчас всё одно-пользовательское: один глобальный `ST`, один набор фильтров, один портфель.
Для внешних юзеров нужно:

- **Личность юзера** = pubkey подключённого кошелька (вход через Connect Wallet, без паролей).
- **Состояние на каждого юзера**: фильтры / стратегия / настройки бота / позиции — свои у каждого
  (вместо глобального `ST` → хранилище по `pubkey`).
- **Подпись в браузере**: `do_buy`/`do_sell` LIVE-путь меняется с «сервер исполняет» на
  «сервер строит tx → браузер подписывает → сабмит».

## 6. Что УЖЕ готово (бэкенд)

Эти «мозги» есть — переиспользуем:
- воронка скрининга (`screen_once`, `hard_gates`, `priority_score`, LLM-судья);
- ABC Alpha v1 (`strategy.py`) + бэктест (`backtest.py`);
- приватные «умные деньги» (`wallets.py`) — сигнал, не копитрейд;
- бот-логика (`bot.py`) — входы/выходы/дисциплина;
- API фильтров / стратегии / бота (`/api/filters`, `/api/strategy`, `/api/bot/*`).

➡️ Не хватает: wallet-connect, построение tx, мультиюзерность, UI-панель настроек,
выбор из нескольких стратегий (сейчас захардкожена одна).
